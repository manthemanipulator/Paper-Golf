PAPER GOLF - DISCORD FEEDBACK / FUTURE IDEAS
(brainstormed July 17, 2026 - nothing below has been built yet)

--------------------------------------------------
1. KEYBOARD SHORTCUTS (desktop)
--------------------------------------------------
Request: a player on computer wants keyboard controls instead of only
clicking buttons.

Decided:
- Spacebar = Roll

Still open:
- Putt key: Shift was requested ("feels more ergonomic"), but flagging a
  real quirk first - Windows has a built-in "Sticky Keys" accessibility
  feature that pops up an OS dialog if Shift is tapped 5 times in a row
  with no other key in between. Could be annoying during a quick run of
  putts. Alternatives with no such risk: Enter or Ctrl. Need a final call
  before building this.
- Should Reroll also get a key (e.g. "R"), or just Roll + Putt?

Implementation notes: no keyboard handling exists in the game at all
today, so this is a clean addition. Needs to respect button disabled
state (can't roll/putt out of turn) and not fire while a text field
(e.g. initials entry) has focus.

--------------------------------------------------
2. CASUAL MODE WIND + NEW "NO-STAKES HARD MODE"
--------------------------------------------------
Request: a player felt casual mode's wind (which currently changes on
every single roll, same as every other mode) is too chaotic. Recommended
casual only re-roll wind once per hole, and add a harder mode that keeps
today's per-roll wind behavior for players who want the challenge.

Decided:
- Casual: wind set once per hole instead of every roll.
- New mode: keeps current per-roll wind behavior (today's casual
  difficulty). No leaderboard / no stakes - matches how casual itself
  has no leaderboard today. Purely for players who want it harder.
- Name TBD (not "Pro" - need a better name whenever this gets built).

Implementation notes: wind is generated by updateWeatherForStroke(),
currently called at hole start AND after every roll/reroll for every
mode with no per-mode branching. Fix is just gating that per-stroke
call behind mode.

--------------------------------------------------
3. RANDOM LEADERBOARD - TIME WINDOW TOGGLE
--------------------------------------------------
Request: random mode's leaderboard only shows the top 10 scores even
though 40+ scores get posted some months. Asked about a way to switch
between monthly / weekly / daily views.

Decided:
- Keep the display capped at 10 (screen real estate is limited) -
  becomes a toggle between Daily / Weekly / Monthly views instead of
  a longer list.

Implementation notes: no backend changes needed. submitScore already
keeps one row per player per month for random mode (their personal
best that month), and that row's timestamp reflects when it was
actually set. A Daily/Weekly/Monthly toggle can just filter that same
monthly data client-side by timestamp - consistent with how daily
mode's own leaderboard already works (one PB per player per day).

--------------------------------------------------
4. CLICKABLE PLAYER COUNT -> COUNTRY BREAKDOWN POPUP
--------------------------------------------------
Request: make the online player count (top of screen) clickable, opening
a popup listing active players by country (flag emoji + count) - "I have
people playing all over the world."

Still open - two approaches, need a decision:
- Simple (recommended to start): client guesses its own country from
  browser settings already available (navigator.language region code,
  or IANA timezone) - no new backend, same trust level already accepted
  for date-bucketing. Not perfectly accurate (VPNs, browser language
  set differently than actual country) but fine for a fun/cosmetic
  feature.
- Accurate: real IP-based geolocation, requires a new Cloud Function
  plus a third-party geo-IP lookup. Note: Firebase Analytics/GA4 already
  geolocates users by IP, but that data only lives in the dashboard for
  historical reporting - it can't be queried live by the running app, so
  it doesn't shortcut this.

Implementation notes if going the simple route: piggybacks on the
online_users presence system already built (heartbeat timestamp written
every 60s) - add a country code alongside the timestamp. Country code
converts to a flag emoji with a one-line Unicode trick, no emoji library
needed. New modal in the same visual style as the leaderboard/stats
overlays, opened by clicking the player-count display.
